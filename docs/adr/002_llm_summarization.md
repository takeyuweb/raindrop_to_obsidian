# ADR-002: Claude Haiku による自動要約

## ステータス

承認済み

## 日付

2026-03-09

## コンテキスト

Raindrop.io から取得したブックマークを Obsidian デイリーノートに記録する際、後から内容を見返したり検索したりするために、各ブックマークの内容を把握できる要約が必要である。

### 現状の問題点

- タイトルと URL だけでは、後から見返した時にどのような内容だったか思い出せない
- ブックマークが増えると、特定の情報を探すのが困難になる

### 制約条件

- 毎日自動実行されるため、人手を介さず要約を生成する必要がある
- コストを抑えたい（日次で数件〜十数件程度の処理）
- 日本語で要約を生成する必要がある

## 決定

Anthropic Claude Haiku（claude-haiku-4-5-20251001）を使用して、各ブックマークの自動要約を生成することを決定した。

### 実装方針

1. ブックマークのタイトル、URL、抜粋、タグ、コレクション、ノート、ハイライトをコンテキストとして LLM に渡す
2. 「何についてのページか」「なぜ重要か・何が学べるか」を含む2〜3文の日本語要約を生成する
3. コスト効率のため Haiku モデルを使用する

## 結果

### ポジティブな影響

1. **後からの検索・見返しが容易になる**
   - 日本語の要約文があることで、Obsidian の全文検索で内容ベースの検索が可能になる

2. **完全に自動化できる**
   - 人手を介さず、cron 実行時に要約が自動生成される

3. **Haiku モデルによる低コスト運用**
   - 1件あたりの入出力トークン数が少なく、日次数件の処理ではコストが低い

### ネガティブな影響・トレードオフ

1. **要約の品質はブックマークのメタデータに依存する**
   - ページ本文を取得しているわけではなく、タイトル・抜粋・ハイライトから要約を生成するため、メタデータが乏しい場合は要約の精度が下がる
   - 対策: ハイライトやノートを積極的に付けることで改善可能

2. **API コストが発生する**
   - Anthropic API の利用料金が発生する
   - 対策: Haiku モデルの使用でコストを最小化。日次数件の処理では実用上無視できる水準

3. **API の可用性に依存する**
   - Anthropic API が停止している場合、要約生成が失敗する
   - 対策: 要約失敗時は「（要約取得失敗）」と記録し、ブックマーク自体の記録は継続する

## 代替案

### 案1: 要約なし（メタデータのみ記録）

**概要**: タイトル、URL、タグ、ハイライトのみを記録し、要約は生成しない

**メリット**:
- 外部 API への依存がない
- コストゼロ
- 実装がシンプル

**デメリット**:
- 後から見返した時に内容を把握しにくい
- Obsidian での検索がタイトルとタグに限定される

**却下理由**: 本プロジェクトの主目的である「内容の見返し・検索」に対して不十分

### 案2: 手動で要約を記入

**概要**: ブックマーク保存時に Raindrop.io のノート欄に手動で要約を書く

**メリット**:
- 自分の言葉で正確な要約が残せる
- API コスト不要

**デメリット**:
- 毎回手動で書く必要があり、継続が困難
- ブックマーク時の手間が増える

**却下理由**: 自動化の目的に反する。継続的な運用が現実的でない
